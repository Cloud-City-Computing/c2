## Why this spec exists

Kyle's decision for Wave 6: **a shared suite shell and navigation, and Cloud Codex's interface
brought onto Cloud Command's design tokens.** The two products stay two separately served apps.
There is no third "portal" app and no organization above a workspace: Cloud Command's workspace
picker becomes the suite's home, and each workspace owns exactly one Codex instance.

The rule for sharing, carried from the 2026-08-24 suite decision: **primitives are matched, not
shared.** One token package is shared; each app builds its own components against it, natively
(TSX in Cloud Command, JSX here). Cloud Command builds each shared surface first as the reference,
and Codex matches it, with one exception: Codex's Toast is the reference (D-V, Decision 11).

Everything visible to a self-hoster is either off by default (the suite shell appears only in
suite mode) or a change Kyle has approved explicitly (the palette and the accent picker, D-N,
below).

## Current behaviour, the starting point

**Styling is one file and a handful of tokens.** `src/index.css` is 9,070 lines. Its `:root` block
(`index.css:12-67`) declares 27 custom properties: five surface lightness steps
(`index.css:18-22`), borders and text (`:24-28`), the accent family `--brand-blue*` (`:31-34`),
danger and success (`:37-39`), radii, shadows, layout sizes including a 220px sidebar collapsing to
56px (`:53-54`), and a transition. There are no fonts beyond the system stack (`index.css:13`).

**There is no theme switch.** Zero `prefers-color-scheme` and zero `data-theme` anywhere under
`src/` (`git grep`, `91493a6`). The app is dark.

**The accent picker writes shared primitives.** Eight hues (`src/userPrefs.js:30-39`), applied by
`applyPrefsToDOM` overwriting `--brand-blue`, `-light`, `-dark` and `-hover` on the root element
(`userPrefs.js:58-72`). **18 of the 40 hue-by-surface pairs fail 4.5:1**, violet worst at 2.30:1
(measured by the Wave 6 research).

**Token discipline, measured by the Wave 6 research with `.jsx` and `.js` included:** 745 findings,
of which 646 are literal colours, 77 are accent-position violations and 22 are outline
suppressions; 679 sit in `index.css` and 32 in `userPrefs.js`. By banner, the editor canvas holds
196 of the CSS findings and the GitHub block (from `index.css:1476`) holds 194.

**Dangling references.** Ten `var()` references name an undeclared token with no fallback. One of
them is user-visible: `.btn-oauth` (`index.css:1422-1437`) paints its border, background and text
from `--border-main`, `--bg-surface` and `--text-main`, none of which is declared, so the Google
sign-in button renders with no border and no background. Another is `var(--red)` at
`index.css:8796`.

**Focus, buttons and layers.** The global `:focus-visible` rule is at `index.css:5726`; the button
family (`index.css:357-413`) sets its focus ring as a literal `rgba` shadow (`index.css:374-377`);
there are 22 outline suppressions; `z-index` appears 22 times with 12 distinct raw values; the
modal dimmer blurs what is behind it (`index.css:1229-1235`).

**Dialogs.** `showModal` (`src/util.jsx:559-577`) renders into a global root with no `role`, no
`aria-modal` and no focus management. Its Escape handler removes itself only when Escape closes the
modal (`util.jsx:569-576`), so each modal dismissed any other way leaves one `keydown` listener
behind.

**The Toast leads.** `src/components/Toast.jsx` is the one working toast primitive in the suite
(Cloud Command has none), but its dismiss is `onClick` on a `div` (`Toast.jsx:81-85`), unreachable
by keyboard.

**The shell.** The top bar's brand slot is a link to `/` with the company logo and "Cloud Codex"
(`src/page_layouts/Std_Layout.jsx:165-172`). Signed out, the app shows `NoLoginMessage`
(`Std_Layout.jsx:232-242`) and sends every path other than `/` and `/404` to `/`, dropping the
target (`Std_Layout.jsx:272-276`). A document's address is `/archives/:archiveId/doc/:logId`
(`src/App.jsx:64`), which is what Cloud Command's document chips already compose.

## Decisions this spec records

1. **Tokens come from one Apache-2.0 package**, vendored and pinned. The package holds literals
   only, in `:root` only (brand, the accent ramp, the semantic ramps with a third lighter step,
   the type scale and a `--font-mono`, spacing, radii, motion, avatars and the z-scale), the five
   font faces with their OFL texts, the gates as plain ESM with a fixture corpus, and `brand.json`.
   It ships no components. **Every alias and theme binding belongs to the consumer.** Its home is
   the public Apache-2.0 repository `Cloud-City-Computing/cloud-city-design` (Kyle's decision
   D-L; the repository exists and holds only its LICENSE until the package lands). Cloud
   Command's W6-CMD-20 and W6-CMD-21 build its contents, and Codex vendors a pinned commit of that
   repository. Cloud Command itself stays proprietary.
2. **Vendored, not installed.** The files are copied into `cloudcodex/vendor/cloud-city-design/`
   at a pinned upstream commit, with a per-file SHA-256 `MANIFEST.json`, because the image builds
   from `./cloudcodex` alone (`docker-compose-prod.yml:25-26`) and a self-hoster must be able to
   build offline, with no token and no network. **Never under `public/`**: that directory is also
   the uploads directory the `app_public` volume shadows in both compose files
   (`docs/maps/build-test-and-ops.md` section 6b), so fonts are imported through Vite and hashed
   into `dist/assets/` instead.
3. **Codex keeps its own five lightness steps**, re-expressed in OKLCH with Cloud Command's neutral
   tint, and binds its accent to the package's `--accent-300`. Cloud Command's `--accent-400` would
   measure 3.46:1 on Codex's strongest hover surface (measured by the Wave 6 research). Codex's
   own bindings live under a `--cx-` prefix (`--cx-surface-0`, `--cx-accent`, `--cx-focus-ring`),
   so no new name can collide with one of the 27 legacy names, or with an undeclared name some
   rule already references with a fallback (`--border` is one).
4. **The palette changes once, through a legacy-alias bridge.** The 27 declared properties are
   repointed to the new tokens in one block, so the roughly 1,040 `var()` uses (1,041 in
   `index.css` by `grep`) and every test that selects by class stay unchanged. After that,
   burndowns only replace literals.
5. **The accent picker writes Codex's `--cx-` alias tokens and never a shared primitive**, and its
   eight hues are re-authored as `oklch(0.78 0.12 H)` (approved, D-N). The four that sit within
   15 degrees of a reserved arc (rose near danger, amber near warning, emerald near success, and
   violet on the violet Cloud Command reserves for its Idea type) move off it and are renamed; the
   other four (blue, cyan, pink, lime) keep their names; nothing is removed, and all 40
   hue-by-surface pairs measure at least 4.5:1. Each renamed key maps to its one successor, so no
   saved preference silently resets.
6. **Codex is pinned to `data-theme="dark"`, and light mode stays deferred (D-V): both apps are
   dark-only through Wave 6.** Codex builds no light theme and no theme switch in this track.
7. **Suite mode is off by default** and turned on by one variable, `SUITE_COMMAND_WORKSPACE_URL`,
   the Cloud Command workspace this instance belongs to (on the test box, a page on
   `https://command.cloudcitycomputing.com`, D-J). Suite mode then also requires `SUITE_NAME`
   (Decision 8). With the URL unset the interface is unchanged apart from the palette.
8. **The suite's name is configuration, not a source literal.** In suite mode the server reads
   `SUITE_NAME` from the environment, beside its other `SUITE_*` setting, validates it at boot and
   serves it through `GET /api/suite`; the client never holds a copy. The value lives in the
   instance's environment (on the test box, the snippet Cloud Command's operator link tool prints),
   so renaming the suite changes no file in this repository. A single-source test asserts that
   application source contains zero `Cloud City` literals, the company's legal name
   (`Cloud City Computing`) excepted. Codex shows the name only in suite mode.
9. **The app switcher is a non-modal disclosure of links**, not `role="menu"`: a button with
   `aria-expanded` and `aria-controls`, the current product marked `aria-current`, Escape and an
   outside click close it and return focus. It navigates in the same tab. **It sits in each app's
   existing top-left identity slot, and there is no new suite bar (D-U)**: in Codex, the top bar's
   brand slot.
10. **Codex's visual check is `iris shoot` against a running app, read by a person**, plus the
    static gates. A browser gate is deferred, because jsdom does not substitute `var()` (it
    computes `color: var(--b)` to the string `var(--b)`, measured on jsdom 30; this repo pins
    `^25.0.1`), so the older design's computed-colour tests cannot be built.
11. **Codex's Toast is the suite's shared toast primitive (D-V).** It is the one surface where Codex
    builds the reference and Cloud Command matches it, under the matched-not-shared rule above;
    W6-CDX-23 puts it on the tokens and gives it a real dismiss button first.

## W6-CDX-21. Vendor the shared tokens, fonts and gates, and land the design gate green on day one

### In scope

- Vendor the package into `cloudcodex/vendor/cloud-city-design/` with its LICENSE and NOTICE, and
  a `MANIFEST.json` checksum test whose failure message says where to propose a change (upstream,
  never here). ESLint ignores the directory.
- A Vitest project, `design` (node environment, `tests/design/**`). If W6-CDX-10 has landed it
  sits beside `integration` and is named in `npm test` so W6-CDX-10's project guard accepts it; if
  not, the bare `vitest run` already runs it, and W6-CDX-10 names it when it lands. It runs:
  - the vendored checksum;
  - token discipline over `src/` and `index.html`, `.jsx` and `.js` included, against an
    **exemption ledger** keyed by file and section banner whose total equals the scanner count
    exactly and can only shrink;
  - dangling `var()`, with the live no-fallback defects fixed in the same PR (`.btn-oauth`'s three
    names and Draw.io's `--red`) or placed on the ledger with a reason;
  - contrast over the new bindings, using a declared pair matrix rather than every text token on
    every surface.
- `src/codex.css` under `[data-theme='dark']`, every name `--cx-` prefixed: the five surfaces in
  OKLCH, the accent bound to `--accent-300`, Codex's own primary, secondary and faint text,
  semantic bindings on the third step, and the focus ring. **No component consumes it yet**, and
  because no `--cx-` name exists today, loading it changes nothing on screen.
- `<html data-theme="dark">`, and per-glob coverage thresholds for any new script.

### Done means

`npm run lint`, `npm test`, `npm run test:coverage` and `npm run build` are green. The ledger total
equals the scanner count, with a non-vacuity check. Each gate goes red on a seeded mutation (a raw
hex in a `.jsx`, an `outline: none`, a dangling `var()`, a tampered vendored file), each confirmed
to have landed. `iris` captures before and after are identical apart from the explained OAuth
button fix.

## W6-CDX-25. Shell chrome and the suite identity cluster

### In scope

- Values-only burndown of the top bar, sidebar, main, footer, account button, dropdown, mobile
  bottom navigation and the responsive blocks.
- The raw `z-index` values move onto the shared z-scale, covering `#root`, `#modal-root`,
  `#dropdown-root` and the lazily created `#toast-root`.
- The vendored Inter and Poppins replace the system stack.
- **Suite mode:** `SUITE_COMMAND_WORKSPACE_URL` turns it on and is validated at boot against an
  `http`/`https` allowlist; `SUITE_NAME` is required whenever it is set, validated at boot (1 to
  40 characters, no control characters), and ignored when it is not. Both are documented in
  `.env.example` with no example value that names the suite, and both join W6-CDX-32's
  configuration contract as per-instance entries, because Cloud Command's operator link tool
  prints both into each instance's snippet (W6-CMD-31, which takes `SUITE_NAME`'s value from
  Cloud Command's own single definition); `SUITE_NAME` is marked required with
  `SUITE_COMMAND_WORKSPACE_URL`. `GET /api/suite` is public and returns `{ enabled, name }`;
  `GET /api/suite/links` requires auth and returns the Cloud Command URL, so an unauthenticated
  caller never learns it.
- The single-source test for Decision 8, with a seeded second literal confirmed to turn it red.
- The identity cluster and switcher in the top bar's brand slot (`Std_Layout.jsx:165-172`), the
  top-left identity slot Decision 9 names (D-U: no new suite bar), matching Cloud Command's
  reference (W6-CMD-23) and the shape brief (W6-CMD-22). Cloud Command
  links go to the workspace, "All workspaces" goes to Cloud Command's `/`, both in the same tab.
- With the variable unset, the top bar's DOM is unchanged.

### Done means

A suite-off render test shows the same top bar as before. Suite-on tests cover the disclosure's
keyboard contract. Route tests confirm `/api/suite` hides the URL. A boot test rejects an invalid
URL. A z-index gate shows every `z-index` references a token, with a non-vacuity floor of 12. The
shell sections have zero findings. `iris` captures sit beside Cloud Command's cluster at desktop
and mobile widths.
