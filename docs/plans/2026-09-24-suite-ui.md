# Plan: suite UI track

Implements [`../specs/2026-09-24-suite-ui.md`](../specs/2026-09-24-suite-ui.md).

> **For agentic workers:** REQUIRED SUB-SKILL: use `superpowers:subagent-driven-development` to
> implement this plan task by task, one fresh subagent per task, with review between tasks. This is
> the standing convention for a written plan in this repo (`docs/plans/README.md`), not a choice to
> re-present. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Cloud Codex's colours, focus, buttons, dialogs and shell resolve from the shared token
package, gated so they cannot drift back, and in suite mode Codex carries the suite's identity
cluster, keeps deep links through sign-in, and links a document to the tasks that reference it.

**Architecture:** the package is vendored into `cloudcodex/vendor/cloud-city-design/` with a
checksum manifest. A fourth Vitest project, `design`, runs the package's plain-ESM gates over this
tree against an exemption ledger that can only shrink. `src/codex.css` binds Codex's aliases to the
package's primitives; a legacy-alias bridge repoints the 27 existing properties so class names and
class-selecting tests never change. Suite mode is one environment variable.

**Tech stack:** React 19, Vite 7, plain CSS custom properties in OKLCH, Vitest 4 + jsdom, the
package's `node:test`-clean ESM gates, `iris` for looking.

**Preconditions, from Cloud Command:** the package exists (W6-CMD-20, W6-CMD-21), and Kyle has
answered the spec's open questions 1 (package home) and 2 (the palette). The shell and deep-link PRs
need W6-CMD-22 to W6-CMD-25 as each section says.

## Before every PR

- [ ] `git fetch origin && git switch -c <branch> origin/main`; re-derive anchors by name.
- [ ] Re-run the gate and record the ledger total before touching anything:
      `npx vitest run --project design` (from PR 1 on; `npm test -- --project design` would add
      the flag to the ones the script already names and run everything).
- [ ] `iris shoot` every route the PR touches, **before** the change, at 1280 and 390 pixels wide,
      into `docs/research/<pr-topic>-<date>/before/`. `iris`'s `pass` means only "not blank and
      nothing threw", so a person reads every image.
- [ ] Before `gh pr create`: an adversarial review (the `momus` reviewer); then CI to green.

## Global constraints

The identity plan's global constraints apply. In addition:

- **Values only, class names kept.** Tests select by class (SearchBox 17 places, ReadOnlyContent 12,
  and others); a renamed class is a broken test that was right.
- **No `position`, `overflow` or `transform` change on or around `.editor-container` or `.tiptap`.**
  Every comment highlight and remote cursor is positioned against them, with no test coverage.
- **The vendored directory is never edited here.** A change to a primitive is a package PR upstream,
  then a re-vendor PR here, and the checksum test's failure message says exactly that.
- **Suite mode off means the markup is unchanged**, pinned by a render test in every PR that touches
  the shell or the front door.
- **After-captures** of every touched route go beside the before-captures, and the PR body explains
  every visible difference.
